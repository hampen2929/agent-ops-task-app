## 記録の境界

- 開始時のアプリ: `e3752aa`。仕様初稿: `716a249`。既存テスト9件は成功し、型チェックとLintも成功した。
- ユーザーからの依頼は「mergeしながら全て書き切ってください」。未決の入力境界はCodexが設計案として補完し、検証してからマージする。
- 実装・仕様整理はCodexが担当する。リポジトリに既設のAI Reviewワークフローの結果を、別のレビューとして記録する。手動の役割切替と、独立したエージェントの実行を区別する。

## 実際に見つかった不具合

日付計算の初稿では、untilによる正常終了より先に日付上限を検査していた。9999-11-30をinterval 100、until 9999-12-31、today 9999-11-01で完了する入力で再現した。daily / weekly / monthlyの3ケースが同じ原因で失敗した（欠陥を3件とは数えない）。`until-overflow-before.txt` が修正前のログ。

次回候補がuntilを越える場合は、対応範囲外の日付を構築する前に次回なしを返すよう修正した。終了条件のない真の範囲超過はエラーのままとし、保存層で現在タスクを完了にしないことも検証した。

## 実装後の検証

`final-checks.json` と `final-*.txt` にコードの対象コミットと終了コードを記録した。既存9件を変更せず、合計70件が成功。追加61件は日付、生成と終了、期限の窓、HTTPの境界を検証する。テスト件数は品質の比率や欠陥検出率を表さない。

型チェック・Lintも成功。package.json / package-lock.jsonと既存2テストファイルは開始時の版から変更していない。HTTPのテストは127.0.0.1の一時ポートで実サーバーに要求を送り、外部サービスへは送信していない。日付はテスト用引数を注入した。
