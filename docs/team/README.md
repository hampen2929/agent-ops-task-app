# 繰り返しタスクを開発する最小チーム

この定義は2026-09-05の書籍実走で使った役割と成果物を再利用するためのもの。マルチエージェントを起動する設定ファイルではない。

| 役割 | この実走の担当 | 入力 | 出力・終了条件 |
|---|---|---|---|
| 依頼者 | リポジトリ所有者 | 書籍完成の依頼 | 執筆・実装・検証・PRマージを委任 |
| 仕様整理・実装 | Codex | docs/specs/recurring-tasks.md、既存コード | 未決事項の確定、T1〜T5、追加テスト |
| 受け入れ検証 | 同じCodexが観点を切り替える | 仕様の受け入れ条件 | 既存テスト保存、境界・HTTPテスト、検証ログ |
| 差分レビュー | 既設のAI Reviewワークフロー（Claude Code） | PR差分、.github/prompts/review.md | 構造化した指摘とPRレビュー |
| 統合 | Codex（依頼者からの委任範囲内） | 対象HEAD、CI、レビュー指摘 | 未解決事項を評価して同じHEADをマージ |

## 実行の順序

1. 仕様と既存テストを読み、依存追加・既存テスト変更・外部通知を対象外とする。
2. 共通の型（T1）を定め、日付計算（T2）、保存（T3）、本文生成（T4）、HTTP接続（T5）を実装する。この実走では直列に実施した。
3. 失敗した入力・期待値・ログを残す。原因を修正し、既存を含む全テスト、型、Lintを通す。
4. PRを作り、既設のCI・AI Reviewを待つ。ジョブの成功とレビュー本文の指摘を両方読む。
5. 修正した場合は新しいHEADで検証し直す。マージ権限はこの実走の委任であり、テンプレートをコピーした別案件には引き継がれない。

## 作業者に渡す依頼の例

仕様を原本として、繰り返しタスクと期限リマインドの本文生成を追加してください。T1の型を先に確定し、既存の9テストと依存・設定は変更せずに、月末の復帰、遅れて完了した場合の周期、count / until、二重完了、失敗時の状態保存、HTTP経由の呼び出しを検証してください。不明な仕様は実装で黙って決めず、決定記録に残してください。結果には対象コミット、実行コマンド、終了コード、未検証事項を含めてください。

## 停止条件

仕様の原本が不明、秘密情報や外部送信が必要、既存テストの期待値を変える必要がある、同じ修正が検証を通らない場合は、変更を広げず根拠を添えて依頼者へ返す。予算や再試行数は実行環境で別途設定する。このMarkdown自体には強制力がない。

独立したQAエージェント、複数実装者の並列実行、所要時間の比較実験はこの実走には含まれない。
